## Still open

### High — [V4.1.3] Change approve uses the project manager

`apps/server/src/changes/changes.service.ts:326` (`approve`, and the same `assertCanApprove` call on reject and on an Approved / Rolled Back status patch).

A project manager who is not the creator’s `reports_to_id` can approve. An Admin can skip that manager. Service requests already use `nextApproval`. Changes do not. The change tests lock the current single-step project rule.

**Fix:** Wire those three paths to `nextApproval` (creator `reports_to_id`; Admin cannot skip the manager).

### High — [V14.2.1] `braces` ≤3.0.3 — no patched release

`pnpm audit` path: `vercel` → `@vercel/fastify` → `ts-morph` → `fast-glob` → `micromatch` → `braces` (39 paths, also the shadcn CLI). Advisory: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). Patched versions: **none**.

Not on the API request path. It is the Vercel CLI and shadcn CLI glob helper. A deeply nested brace pattern can exhaust the stack inside those CLIs.

**Fix:** None until `braces` publishes a release. Do not override it to a made-up version.

### Moderate — [V14.2.1] `uuid` 8.3.2 via autocannon

Path: `apps/server` → `autocannon` → `hyperid` → `uuid@8.3.2`. Advisory: [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Patched versions: `uuid` ≥11.1.1.

`hyperid` loads it with `require("uuid")` and only falls back to `uuid.v4` when `crypto.randomUUID` is missing. `uuid` 11 does not support that `require`. Forcing it breaks the load-test tool. The vulnerable buffer APIs (`v3` / `v5` / `v6` with a caller-supplied buffer) are not what `hyperid` calls.

**Fix:** Leave it until `hyperid` or `autocannon` depend on `uuid` 11.
